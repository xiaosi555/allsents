# 醒图页改版实施记录（阶段 A / 首轮隔离）

> 仓库：xiaosi555/allsents  
> 开发分支：ui/xingtu-redesign-preserve-legacy  
> 原页面：ArticleEditorScreen  
> 新页面：ArticleEditorRedesignedScreen  
> 目标：保留原醒图页面，以新版页面作为首页入口；在现有视觉风格基础上逐步统一 UI、面板、弹窗和交互。

## 1. 不可破坏约束

- 原有 `ArticleEditorScreen` 不删除、不覆盖，保留为旧版页面。
- 新版从现有编辑器完成全部构建期补丁后的源码生成，继承原有文章、WebView、素材、模板、图层、组件、表格、导入导出及撤销重做能力。
- 不改动文章数据结构、Store 持久化结构、HTML 编辑内核和素材 ID 规则。
- 不大幅改变原有背景、底纹、主色和页面气质；新版首先统一交互和面板尺寸。
- 首页新增“醒图”入口，打开新版；MainActivity 同时保留旧版独立路由，便于对照和回退。
- 旧版页面后续不再接收新版专属 UI 改动，除非发现必须修复的共用业务缺陷。

## 2. 已核对的现状

- 编辑器采用 Compose 原生工具界面 + Android WebView contenteditable 画布。
- 当前源码包含文字、图片、组件、样式、图层、文档、图文模板等功能分类；现有功能入口数量不能仅按静态按钮数认定，动态列表、弹窗和上下文工具也必须盘点。
- 构建不是直接编译 overlay 单文件：`apply_article_editor.py` 复制基础源码后，多个阶段脚本依次修改编辑器；必须在所有旧功能补丁完成后再生成新版页面。
- 原有返回处理仅覆盖文章列表、预览和退出保存，未覆盖输入法、临时编辑、对象选中、二级面板及多层弹窗的逐级返回。
- 原有二级面板已具备独立滚动和拖动高度机制；新版需在继承现有实现后统一为 200–400dp，默认不展示拖动滑块。
- 二级面板打开时应主动隐藏输入法，同时保留当前 WebView 选区和对象引用。

## 3. 本轮实施内容

### 3.1 页面隔离

新增构建脚本 `native-overlay/create_redesigned_xingtu_editor.py`，在旧版编辑器全部现有补丁执行后，将最终源码复制为 `ArticleEditorRedesignedScreen.kt` 并更名为独立 Composable。原页面仍由 `ArticleEditorScreen.kt` 提供。

### 3.2 首页入口和路由

- 首页“醒图”入口指向 `xingtu_article_editor`。
- `xingtu_article_editor` 指向 `ArticleEditorRedesignedScreen`。
- `xingtu_article_editor_legacy` 保留指向 `ArticleEditorScreen`。
- 秀米页面路由保持独立，不与醒图页面合并。

### 3.3 新版面板规则

- 面板默认高度 200dp，最大 400dp。
- 默认隐藏顶部拖动滑块，只保留窄的触摸拖动区域。
- 只有检测到向上拖动时才显示滑块。
- 面板关闭时重置滑块显示状态。
- 打开文字、图片或画布二级面板时主动隐藏输入法，不主动清除当前选区。

### 3.4 新版返回协调器

新版使用统一 `handleEditorBack()` 处理系统返回和顶部返回按钮，按当前状态逐级退出：
1. 最上层弹窗/预览窗口。
2. 插入菜单、更多工具和模板子导航。
3. 画布或工具二级面板。
4. 预览状态。
5. 正在编辑的文字状态，恢复到文字选中状态。
6. 文字选区。
7. 图片、组件、多选等对象选区。
8. 保存并退出编辑器。

输入法仍优先由 Android IME 自身消费系统返回；二级面板打开时主动隐藏 IME。必须通过真机验证 IME 返回优先级和不同 Android 版本行为。

- 逐项核查新页面中的所有旧功能入口和回调是否完整。
- 对图片裁切、调色、素材引用、WebView 生命周期和异步回调进行回归。
- 统一所有弹窗标题栏、操作区、输入控件、间距和关闭规则。
- 统一所有二级面板视觉样式，但保留各功能所需的专属内容布局。
- 检查首页入口位置、图标、无障碍描述和点击热区。
- 在 CI 运行后检查最终合成 Kotlin 源码，而不只检查 overlay。
- 真机测试键盘、手势返回、面板拖动、画布选区和多层弹窗。
