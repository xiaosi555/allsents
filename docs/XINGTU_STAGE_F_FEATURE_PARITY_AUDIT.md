# 醒图改版阶段 F：功能清单对照与交互验收基线

## 目标

阶段 F 不重写业务功能，而是建立旧版与新版之间的功能保真检查，防止面板整理、弹窗统一和返回逻辑调整造成工具项、状态、面板分支或业务入口缺失。

## 自动静态审计

`native-overlay/audit_redesigned_xingtu_stage_f.py` 在阶段 E 之后运行，逐项对照：

- `EditorTool("…")` 工具标签：按多重集合比较，检查数量与重复项，确保新版没有少于旧版。
- 面板分支：分别读取旧版 `EditorPanel` 与新版 `RedesignedEditorPanel`，检查分支集合完整；新版同时包含图片裁切/调色专用分支。
- Compose `remember` 状态：旧版状态集合必须是新版状态集合的子集。
- `AlertDialog`、`DropdownMenu`、`Dialog` 调用点数量：外观统一不得删掉弹窗入口。
- WebView 选区桥接、Range 保存/恢复、裁切、图片替代文本、查找替换、文章信息、历史版本、布局、兼容性报告、文章包预览和模板预览等关键入口。
- 返回协调器层级、图片素材选择窗口独立关闭分支，以及新版/旧版独立路由。

## 人工交互回归矩阵

| 场景 | 预期行为 | 验收方式 |
|---|---|---|
| 文字范围选中 | 文字浮动工具栏与对应底部导航出现 | 真机点选、拖动选区 |
| 文字编辑 + 输入法 | 输入法可正常输入；系统返回先收起输入法 | 真机输入与系统返回 |
| 输入法收起后第一次返回 | 恢复原文字 Range，仍处于文字选中态 | 检查选区、光标和工具栏 |
| 再次返回 | 清除文字选区，不离开编辑页 | 真机连续返回 |
| 图片选中 | 图片工具项、裁切和调色二级面板可用 | 导入图片后逐项操作 |
| 图片素材选择窗口 | 返回只关闭素材窗口，不清除画布图片选区 | 打开素材选择后返回 |
| 图片裁切/调色 | 面板可点击，修改实时同步画布，不崩溃 | 多次裁切、调色、取消与确认 |
| 组件/卡片/SVG/表格 | 对象选择与相应工具面板保持联动 | 逐类插入、选中、修改 |
| 多选对象 | 返回先退出当前对象/多选状态，不直接离页 | 多选后连续返回 |
| 一级导航与二级面板 | 一级导航作为入口；面板出现时不重复显示一级导航 | 检查面板层级和遮挡 |
| 二级面板交互 | 面板内部按钮、滚动和滑块可操作 | 点击、滚动、拖动 |
| 二级面板高度 | 初始不低于 200dp，展开不超过 400dp | 真机测量与拖动 |
| 浮动子菜单 | 先关闭子菜单，父面板保持打开 | 打开子菜单后返回 |
| 删除确认/其他弹窗 | 只关闭最上层弹窗，不跳过父页面 | 逐类打开并返回 |
| 文章列表/预览/历史/模板 | 返回逐层关闭当前窗口 | 逐类进入、返回 |
| 保存并离开 | 只有所有选区和临时层退出后才保存并离开 | 连续返回并核对内容 |

## 阶段边界与结果口径

- 自动脚本属于源码静态审计，不等于 Kotlin 编译成功。
- 由于本轮明确暂不构建 APK，阶段 F 不会触发 Android 构建，也不会声称真机验收通过。
- 需要 APK/设备验证的项目必须标记为“待真机验收”，不能以源码存在或静态检查替代。
- 任何发现的工具项缺失都应先修复新版生成链，再进行后续视觉微调；不得通过删除旧版入口来规避差异。
