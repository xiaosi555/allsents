# 公众号文章编辑器技术方案

## 1. 目标与边界

在现有「排版 / 我的」原生 Android 应用中新增独立的公众号文章编辑器。编辑器是新增能力，不替换现有排版预览、文案随机读取、素材插入、版式模板及复制逻辑。文章以 HTML 富文本保存，保证复制到微信公众号图文编辑器时尽可能保留样式。

## 2. 现有工程依据

- `000_拾万句.html`：现有 Web 版页面、`appData.files.text` 文案模块结构、分类和本地持久化方式。
- `native-overlay/.../data/Models.kt`：原生数据模型；字段需与 JSON 备份兼容。
- `native-overlay/.../data/Store.kt`：本地 `app_data.json` 持久化、导入导出和数据规范化。
- `native-overlay/.../ui/MyScreens.kt`：我的首页、文案模块列表/宫格/排序/新增/编辑/删除交互。
- `native-overlay/.../ui/LayoutScreen.kt`：排版顶部栏、预览 WebView 和编辑入口。
- `native-overlay/.../ui/AppViewModel.kt`：跨页面共享数据、预览和保存业务。
- `native-overlay/.../ui/PreviewWebView.kt`：现有 WebView 桥接方式，可参考但不复用排版预览的编辑态，避免两套编辑逻辑互相覆盖。

## 3. 入口与页面

### 3.1 排版页入口
- 在顶部「编辑」右侧增加一个仅图标的样式入口（线性图标，不显示文字）。
- 点击后进入独立文章编辑器；返回时回到原排版页，原排版编辑状态和预览数据不丢失。
- 样式入口与现有「编辑 / 完成」状态并存，不改动原编辑按钮行为。

### 3.2 我的 - 样式
- 我的首页增加「样式」入口。
- 样式管理复用文案模块的列表/宫格切换、排序、新增、详情编辑、删除和空状态交互。
- 每条样式模块包含：名称、用户自定义分类、富文本 HTML 内容、更新时间。
- 分类不写死为「朋友圈 / 名句」；用户可自行输入、创建和选择分类。
- 删除样式模块或分类前进行确认；删除分类时若仍有关联样式，必须提示并让用户选择迁移或取消，不能静默丢数据。
- 旧版备份 JSON 缺少新增字段时默认空列表；导入旧备份不丢失原有账号、文案、版式、配图、动图、Emoji、往期数据。

### 3.3 文章编辑器
- 独立全屏页面，顶部提供返回、文章标题、保存状态/保存操作。
- 编辑区采用 WebView `contenteditable` 富文本内核；Compose 原生工具栏负责命令、媒体选择、分类/样式模块选择和页面状态。
- 编辑内容以 HTML 保存，不把 HTML 转成纯文本覆盖。
- 工具栏与编辑区域分离，编辑区域支持滚动、文本选择、光标定位和软键盘。

## 4. 编辑能力清单

### 文本与段落
- 撤销 / 重做、全选、清除格式。
- 粗体、斜体、下划线、删除线、上标、下标。
- 字体大小、字体/字族、文字颜色、背景高亮。
- 段落正文、标题 H1–H4、引用块、代码块、分隔线。
- 左对齐、居中、右对齐、两端对齐。
- 有序列表、无序列表、缩进 / 减少缩进、行距和段前段后间距。

### 内容与媒体
- 插入/编辑/删除超链接。
- 插入图片（本地图片与网络图片）、图片替代文字、宽度/对齐。
- 插入表格、增删行列、单元格编辑。
- 插入音频/视频链接或占位卡片；对公众号不支持直接承载的媒体格式，保留可复制的链接/卡片，不伪称可直接发布。
- 插入日期、特殊符号、Emoji、空行和分隔符。
- 支持粘贴文本与 HTML；对不安全脚本、事件属性和危险 URL 做清理。

### 公众号排版
- 常用公众号正文宽度和移动端预览。
- 文章标题、摘要、作者、正文分区。
- 段落间距、首行缩进、字间距、行高、两侧边距。
- 图片自适应、居中、圆角、说明文字。
- 引用、提示框、编号列表、分割线等常用公众号组件。
- 提供编辑视图与阅读预览切换。
- 复制富文本 HTML 到剪贴板，附带纯文本回退；复制失败时给出明确反馈。

## 5. 自定义样式分类如何进入编辑器

- 「我的 - 样式」管理的分类名称作为编辑器中的功能分类标签。
- 选中分类后展示该分类下已保存的样式模块。
- 点击样式模块将其 HTML 片段插入当前光标位置；若没有有效光标，则追加到正文末尾。
- 新增/修改/删除样式模块后，编辑器分类和内容即时刷新。
- 空分类不隐藏；显示空状态和新增入口，方便先建分类再逐步积累组件。

## 6. 数据模型与兼容

新增根字段：
- `styles: StyleModule[]`
- `articles: ArticleDocument[]`

`StyleModule`：`id`、`name`、`category`、`html`、`updatedAt`。
`ArticleDocument`：`id`、`title`、`html`、`createdAt`、`updatedAt`。

所有新增字段均提供默认值。Gson 反序列化旧备份时缺字段按空列表处理。导入/导出 JSON 保留新增数据。排序仅改变样式模块顺序，不改动 HTML 内容和 ID。

## 7. 安全、稳定与验收

- WebView 禁止任意网页导航和文件访问；仅允许本地编辑文档与必要的图片 URI。
- 图片本地导入时复制到应用私有目录或编码为可持久化资源，不能只保存临时 content URI。
- HTML 清理脚本标签、事件属性和危险协议；不删除合法内联样式、图片、表格、SVG 等公众号常见结构。
- 自动保存草稿；页面返回、进程重建、旋转和软键盘弹出时不得丢失未保存内容。
- 导入旧 JSON、导出新 JSON、再次导入后验证样式模块和文章内容一致。
- 验收必须实际点击每个工具栏功能，检查光标处插入、保存后重进、复制到外部富文本编辑器的结果。
- 构建成功只代表编译通过；还需单独核验 APK artifact，并在可用设备上进行交互安装验证。

## 8. 实施顺序

1. 数据模型、Store 兼容、备份导入导出。
2. 我的 - 样式管理（按文案模块的交互规范）。
3. 独立文章编辑器 WebView 内核和自动保存。
4. 富文本工具栏、媒体插入、公众号组件和预览。
5. 排版页图标入口、分类/样式模块联动。
6. 旧数据兼容测试、编译、APK artifact 检查和设备验收。
