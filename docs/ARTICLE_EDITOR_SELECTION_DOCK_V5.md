## 二、当前问题定位

旧实现存在三个薄弱点：

1. 文字/图片选中主要依赖冒泡阶段的 `click` 事件和 `event.target`，未统一处理触摸命中、文本节点、图片外层容器。
2. 首次文字点击时在 `pointerdown` 阶段改变整个编辑根节点的 `contentEditable`，可能影响后续 click 目标与焦点流程。
3. 空白区域根据最外层模块是否含文本判断，容易把模块内留白错误识别为组件。

底部导航状态由 `NativeEditor.selectionChanged` 的结构化选择状态驱动，不能只依赖 `imageSelected` 或 `textSelected` 两个展示布尔值。

## 三、V5 交互状态机

| 画布命中 | 当前对象状态 | 底部导航 |
|---|---|---|
| 点击图片本体 | 选中图片、清除文字/组件选中 | 图片导航 |
| 点击文字所在行 | 选中当前文字块、显示选中轮廓 | 文字导航 |
| 再次点击同一文字块 | 恢复可编辑状态并把光标放到触点附近 | 文字导航 |
| 点击表格/SVG/视频等组件本体 | 选中组件 | 组件导航 |
| 点击画布空白区域 | 清除图片/文字/组件选中 | 默认导航 |
| 点击画布外区域 | 不改变画布对象状态 | 保持当前状态 |

### 对象命中规则

- 先将文本节点规范化为所属元素。
- 优先命中图片本体，再命中文字块，最后识别表格、SVG 等结构组件。
- 文字识别支持段落、标题、列表、引用、预格式文本、表格单元格，以及包含直接文本节点的容器。
- 不命中对象的画布内位置一律按空白画布处理，不再根据外层容器是否包含其他文字而误选整个组件。
- 使用 `elementFromPoint` 对触摸点进行二次命中校验，避免事件目标被外层容器或编辑状态切换影响。

### 选择状态与工具栏同步

`selectionChanged` 是底部导航的单一状态来源：

- `TEXT_BLOCK / TEXT_RANGE / CARET` → `TEXT`
- `IMAGE` → `IMAGE`
- `COMPONENT / TABLE / LAYOUT / MULTI_BLOCK` → `COMPONENT`
- `NONE` → `DEFAULT`

清除选择时同时清理图片、文字、组件状态和上下文浮动工具，防止旧对象残留。文字选中轮廓仅用于编辑器反馈，不写入保存的文章 HTML。

## 四、手机触控与输入

- 首次点击文字只选中，不主动打开键盘。
- 再次点击同一文字块进入编辑，并优先通过触点定位光标；无法定位时回退到段尾。
- 图片点击只选择图片，不把图片所在段落误判成文字。
- 组件自由拖动模式下，选择事件不抢占拖动逻辑。
- 二级工具面板仍由原有 Compose 面板承载；同一对象继续编辑时保留当前面板，切换到不同对象时关闭旧面板并显示新对象的底部导航；点击空白则关闭面板并恢复默认导航。

## 六、技术参考

- DOM click 事件在指针按下/抬起目标变化时可能落到两者共同祖先，不能假设 `event.target` 始终等于用户实际点中的叶子节点：  
  https://developer.mozilla.org/en-US/docs/Web/API/Element/click_event
- Pointer Events 统一鼠标、触控和触控笔输入，并定义浏览器命中测试：
  https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events
- `elementFromPoint()` 返回指定视口坐标处最上层元素，用于复核真实触点：
  https://developer.mozilla.org/en-US/docs/Web/API/Document/elementFromPoint
- Android WebView 的 `evaluateJavascript` 在 UI 线程异步执行；JavaScript bridge 回调需将状态安全投递到主线程：  
  https://developer.android.com/reference/android/webkit/WebView
