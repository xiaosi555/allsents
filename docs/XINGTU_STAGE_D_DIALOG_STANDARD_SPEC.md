# 醒图改版阶段 D：弹窗与独立工作窗口统一

> 目标页面：构建时生成的 `ArticleEditorRedesignedScreen.kt`  
> 旧版 `ArticleEditorScreen.kt` 保持不变。阶段 D 只统一表现层，不迁移业务状态，不删除功能。

## 1. 统一原则

- 统一的是编辑器内部弹窗的视觉外框和操作层级，不把不同业务窗口合并成同一个表单。
- 保留当前深色编辑器工作面和主题强调色；不改中央文章画布、文章 HTML、数据模型、素材 ID 或持久化逻辑。
- 轻量下拉菜单继续作为菜单，不升级成模态窗口。
- 专业工作窗口保留自己的内容结构、预览区、滑块、输入字段和实时回调。
- 关闭、取消、完成、删除、恢复等语义必须保持原样，不能因为按钮外观统一而交换动作。

## 2. 弹窗类型与规范

| 类型 | 统一项 | 必须保留 |
|---|---|---|
| AlertDialog 确认/信息窗 | 16dp 圆角、深色容器、统一标题/正文对比度、无额外色调抬升 | 原 onDismiss、confirm/dismiss 回调、警告文案 |
| 通用输入窗 EditorInputDialog | 继承 AlertDialog 外框规范 | 标题、提示、输入值、输入回调、确认/取消逻辑 |
| DropdownMenu | 12dp 圆角、统一阴影层级、深色菜单容器默认值 | 已有主题容器色、菜单项顺序与点击动作 |
| 专业 Dialog | 统一首层 Surface 16dp 圆角 | 自定义裁切、图片预览、分栏、模块属性等专用内容和内部滚动 |
| 预览窗口 | 统一外框，不合并预览与应用动作 | 模板预览、历史版本预览、图片素材预览 |
| 危险操作确认 | 与普通确认窗同一外框 | 删除文章/模板、整篇模板替换等二次确认 |

## 3. 不得破坏的行为

- HTML 导入预览：创建新文章与替换正文仍是不同动作。
- 文章包导入预览：确认后新建文章，元信息、正文和资源数量仍可查看。
- 文章信息：取消恢复快照，完成保存元信息。
- 历史版本：预览与恢复分离，恢复后仍保留当前版本快照策略。
- 模板：预览、编辑、应用整篇模板、删除分别保留原有流程。
- 图片：裁切、调色、替代文字、网络图片、素材预览仍使用原专用回调。
- 布局：自定义分栏的参数、校验、图片导入和插入画布流程不变。
- 组件：模块属性尺寸、间距、背景、边框、圆角、阴影、对齐和透明度功能不变。
- 查找替换、兼容性报告、导入导出和文档管理功能不变。

## 4. 实施方式

新增 `native-overlay/apply_redesigned_xingtu_stage_d.py`，在 Stage C 之后、最终源码诊断和构建之前执行。

- 仅对生成的新版源码做 patch。
- 对所有 AlertDialog 补齐统一的 shape、containerColor、titleContentColor、textContentColor、tonalElevation；保留已有回调和自定义按钮。
- 对 DropdownMenu 只补齐缺省外观参数，不覆盖已有容器色。
- 对自定义 Dialog 内首层 Surface 统一圆角，不改其颜色和内容。
- 通过括号/代码块平衡扫描定位调用，不使用容易误匹配的全局字符串替换。
- 后置检查所有 AlertDialog 的统一参数和关键业务窗口仍存在。

## 5. 本轮边界

- 不构建 APK。
- 不触发 APK 构建工作流。
- 不宣称 Compose 编译或真机验收通过。
- 阶段 D 后续仍需逐项检查每个窗口的宽度、键盘避让、滚动和关闭语义；阶段 E 再统一返回栈与输入法/选区状态机。
