# 文章编辑器阶段 A：现有功能全量盘点与入口映射

> 仓库：xiaosi555/allsents  
> 分支：main  
> 盘点基准：当前 main 分支的 ArticleEditorScreen.kt、apply_article_editor.py、apply_style_categories.py，以及公众号文章编辑器技术方案.md  
> 本阶段只读盘点，不修改 UI、不删除功能、不改变业务逻辑。

## 1. 盘点结论

当前编辑器已具备文章管理、富文本、图片导入和处理、模块/多选、表格、组件插入、模板库、收藏、历史版本、HTML/Markdown/文章包导入导出、富文本剪贴板和公众号兼容性静态检查等功能。

技术架构为 Jetpack Compose + Android WebView + contenteditable + JavaScript Bridge。Compose 管理原生面板、文件选择器、Bitmap 图片处理和数据持久化；WebView 管理正文 DOM、文字选区、图片/模块选择、插入和格式操作。

**关键发现：**
1. 选中文字或图片时，当前底部工具坞会被隐藏，悬浮窗取代底栏。这与用户要求的“底部功能栏始终存在，悬浮窗叠加出现”不一致。
2. 悬浮工具窗目前只有文字和图片两类；组件、表格、布局、多选操作仍主要依赖底部分类面板。
3. 图文收藏分类来自全部样式分类，而实际内容只过滤收藏项，可能出现空分类。
4. 标题/卡片/图片/布局筛选依赖分类、名称、标签的关键词匹配，不是稳定的结构化类型。
5. 文字状态主要由 click 事件粗略判定；selectionchange 仅保存 Range，没有同步选区类型、折叠状态和坐标。
6. 图片裁切已有 CSS 显示裁切和原生 Bitmap 像素裁切两套机制，后续 UI 必须明确区分。
7. 触屏拖动、多选成组移动、自定义裁切手势、选区恢复、键盘避让和微信粘贴效果仍需真机验证。

“代码已接入”不等于“真机验收通过”。

## 4. 技术职责与当前 Bridge

### Compose 层
页面顶栏、文章列表、底部面板、全部工具、Dialog、文件选择器、Bitmap 裁切、私有素材读写、模板缩略图、ViewModel 数据保存。

### WebView/JavaScript 层
contenteditable、Selection/Range、HTML 插入、文字格式、图片样式与裁切显示、模块选择/复制/删除/排序、多选拖动、表格增删行列、撤销重做、粘贴清理。

### 当前 Bridge 回调
- changed(html)：正文变化
- blockSelected(html)：选中模块 HTML
- imageSelected(html)：选中图片 HTML
- textSelected("1"/"0")：粗粒度文字状态

### 当前缺少的结构化信息
稳定 blockId/imageId、TextBlock/TextRange/Caret 区分、Range 是否折叠、选区矩形坐标、对象类型、多个对象 ID 数组、键盘编辑状态、父容器/布局层级信息。

后续建议增加统一 EditorSelectionState，同时保留旧 Bridge 回调一段时间，避免一次性破坏现有交互。

## 6. 新结构的归属原则

| 入口 | 应放置功能 | 不应放置 |

## 8. 阶段 A 结论与阶段 B 门槛

阶段 A 已建立现有功能目录、入口位置、核心处理函数、数据影响和目标归属。后续不能因为界面重组而删除旧命令。

阶段 B 开始前必须先完成：
1. 统一对象状态模型：None、TextBlock、TextRange、Caret、Image、Component、Table、Layout、MultiBlock、Preview。
2. Bridge 增加稳定对象 ID、选区折叠状态、Range rect、对象类型和多选 ID 数组；暂时保留旧回调兼容。
3. 底部功能栏常驻；悬浮窗独立覆盖，不能隐藏底栏。
4. 文字工具操作前保存 Range、操作前恢复、操作后复核真实选区。
5. 统一字号/字体/颜色配置源。
6. 模板增加结构化 kind/categoryId；旧模板保留原字段，无法判断类型的归为“未分类”，不丢数据。
7. 收藏分类只从收藏项生成，收藏内容、缩略图和素材引用持久化。
8. 图片裁切区分可逆 CSS 显示裁切与生成新 MediaAsset 的像素裁切。
9. 所有旧功能先建立新旧映射，迁移完成前不删除旧入口。
10. 按第 7 节清单回归；编译结果与真机交互验收分开记录。
