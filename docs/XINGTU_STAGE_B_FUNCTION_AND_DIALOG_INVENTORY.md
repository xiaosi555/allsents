# 醒图改版阶段 B：功能入口、弹窗与交互全量盘点

> 基准分支：`ui/xingtu-redesign-preserve-legacy`  
> 盘点对象：构建补丁链最终生成的 `ArticleEditorScreen.kt`  
> 目标页面：`ArticleEditorRedesignedScreen.kt`  
> 原则：只做归类、入口和外观统一，不删除原有能力，不改变文章数据模型、WebView 编辑内核、素材引用和持久化逻辑。

## 1. 页面结构与一级入口

编辑器采用 Compose 外围 UI + Android WebView 文章画布。页面结构分为顶部操作区、中央画布、插入/选区悬浮工具、底部一级导航、二级功能面板和独立弹窗。

| 一级入口 | 内部能力范围 | 二级面板/弹窗关联 | 处理要求 |
|---|---|---|---|
| 文字 | 字符格式、段落、字号、颜色、字体、列表、缩进、行距、字距、日期时间、Emoji、特殊符号、查找替换 | 文字工具面板、文字属性面板、取色、查找替换 | 保留快捷操作与完整属性面板，不把所有文字操作挤进单一列表 |
| 图片 | 本地导入、相册、网络图片、双图/三图组、说明、对齐、图片库 | 图片工具、图片裁切、图片替代文字、图片预览、网络地址输入 | 导入、替换、裁切、调色、位置、边框、圆角、删除和组内排序都必须保留 |
| 布局 | 双栏、三栏、图文左右/上下、左右分割、居中、留白、分割线、自定义分栏 | 自定义分栏工作窗口 | 表格布局生成与画布内后续编辑必须保持 |
| 卡片 | 卡片样式、内容卡片、卡片组件 | 卡片面板 | 逐项盘点现有卡片模板和插入回调，不以静态标题代替功能 |
| 组件 | 组件插入、组件属性、复制、删除、组合、保存组合组件 | 组件面板、模块属性窗口 | 保留原组件类型、样式和可编辑 HTML |
| SVG | SVG 素材插入和 SVG 相关组件 | SVG 面板 | 保留原 SVG 内容与插入逻辑，避免把 SVG 当普通图片处理 |
| 图层 | 图层列表、选中、显隐、锁定、层级移动和对象定位 | 图层面板 | 列表状态必须与 WebView DOM 对象同步 |
| 图文收藏 | 已保存样式、收藏、分类、搜索和复用 | 收藏样式面板、分类管理 | 保留样式 ID、类别 ID、收藏状态和原始 HTML |
| 图文模板 | 整篇模板、局部模板、标题/卡片/图片/布局/SVG/组件子分类、搜索、收藏、预览、编辑和删除 | 模板子导航、模板预览、模板内容编辑、整篇替换确认、删除确认 | 整篇替换必须二次确认；局部模板插入后仍可编辑 |
| 文档 | 文章信息、文章列表、新建、复制、删除、收藏、状态筛选、版本历史、导入导出、预览、兼容性检查 | 文章列表、文章信息、版本列表/预览、HTML 导入预览、文章包导入预览、查找替换、兼容性报告 | 文章元数据、历史快照、资源 ID、草稿/完成状态全部保留 |
| 画布 | 画布/页面相关操作与可拖动的画布工具窗口 | 画布浮层 | 与普通底部工具面板区分，不能让全屏透明层拦截画布点击 |

### 内部面板枚举映射与发现的导航缺陷

源码中的 `EditorPanel` 共 13 个枚举项。当前旧导航通过 `filterNot { it in templateSubPanels || it == TEXT2 }` 同时过滤模板子分类，导致 `IMAGE`、`LAYOUT`、`CARD`、`COMPONENT`、`SVG` 虽然有完整面板实现，却没有直接出现在一级导航中，普通用户只能从模板子导航或对象上下文入口间接触达。这是阶段 B 发现的实际入口缺陷。

- 新版一级主导航：`TEXT`、`IMAGE`、`LAYOUT`、`CARD`、`COMPONENT`、`SVG`、`LAYER`、`STYLE`、`TEMPLATE`、`DOCUMENT`、`CANVAS`。
- 文字属性工作区：`TEXT2`，作为文字二级工作区，不作为重复的一级入口。
- 模板子分类：`TITLE`、`CARD`、`IMAGE`、`LAYOUT`、`SVG`、`COMPONENT`，继续由模板子导航承载。模板子分类代表“模板素材类别”，一级入口代表“直接编辑/插入工具”，两者用途不同，因此保留两处入口不是重复删减。
- `TEMPLATE` 是模板主入口，`templateSubPanel` 负责保存当前模板子分类。

## 2. 弹窗与浮层清单

盘点基准源码中有 20 余个独立窗口/弹层调用点，包含 AlertDialog、Dialog、DropdownMenu 和复用输入弹窗。以下按用途归档；同类窗口可共用外观壳，但不能合并其业务逻辑。

| 类别 | 窗口/弹层 | 当前实现/状态来源 | 统一要求 |
|---|---|---|---|
| 颜色与属性 | 自定义取色 | `showTextColorPicker` | 保留 HEX 输入、预设色、校验和应用回调 |
| 快捷工具 | 更多工具 | `showMoreTools` | 轻量菜单，不应成为全屏页面 |
| 快捷工具 | 图片尺寸下拉 | `floatingMenu=image-width` | 选择后即时应用并关闭 |
| 快捷工具 | 图片裁切比例下拉 | `floatingMenu=image-crop` | 保留比例、自定义像素裁切、恢复原始比例 |
| 快捷工具 | 图片外观下拉 | `floatingMenu=image-style` | 保留圆角、直角、边框 |
| 快捷工具 | 文字字号下拉 | `floatingMenu=text-size` | 选中后即时应用 |
| 快捷工具 | 文字字体下拉 | `floatingMenu=text-font` | 保留全部字体选项 |
| 快捷工具 | 文字颜色下拉 | `floatingMenu=text-color` | 保留全部颜色预设 |
| 画布 | 画布工具浮层 | `showCanvasPopup` | 可拖动、只覆盖自身区域，空白画布仍可点击 |

| 模板 | 模板预览 | `templatePreview` | 预览窗口与应用操作分离 |
| 模板 | 编辑模板内容 | `editingTemplateContent` | 多行内容编辑、保存/取消 |
| 模板 | 删除模板确认 | `deletingTemplate` | 危险操作明确提示 |

## 3. 悬浮工具与非模态窗口

| 入口 | 功能 | 规范 |
|---|---|---|
| 插入悬浮按钮 | 打开文字/图片插入快捷项，可拖动位置 | 不能挡住画布主要内容；打开子菜单后返回先关闭子菜单 |
| 选区悬浮工具栏 | 文字、图片、组件、表格、多选对象快捷操作 | 依据真实选区类型显示，不以旧的布尔状态猜测对象类型 |
| 图片悬浮菜单 | 尺寸、裁切、圆角/边框、替换 | 选择后关闭菜单，保留图片选中上下文 |
| 文字悬浮菜单 | 字号、字体、颜色、粗斜体等 | 选择后即时应用，保留文字 Range |
| 二级底部面板 | 一级导航触发的完整工作区 | 面板覆盖一级导航所在区域，面板内不再重复一级导航 |
| 画布浮层 | 画布工具与定位 | 与底部二级面板分开管理，不能相互覆盖或拦截错误触摸 |

## 4. 返回层级盘点与目标顺序

返回不是页面跳转，而是按当前实际打开状态关闭最内层交互。目标优先级：

1. Android 输入法（系统 IME 自身优先消费返回）。
2. 当前下拉菜单、颜色选择器、轻量浮层。
3. 当前最上层独立弹窗/专业工作窗口。
4. 模板子导航、插入快捷菜单、更多工具菜单。
5. 二级面板（关闭时不清空 WebView 选区）。
6. 正在编辑文字的输入状态（退出编辑并恢复光标/文字选中）。
7. 文字范围选中状态（清除文字范围，但不误清其他对象）。
8. 图片/组件/表格/布局/多选对象选中状态。
9. 预览状态。
10. 文章列表或文档子状态。
11. 保存并退出编辑器。

注意：真实顺序必须按“当前最上层窗口”判定，不能仅靠固定 if 顺序推测。父窗口关闭时要恢复父窗口的输入、选区和滚动位置。

## 5. 现有代码中需要修正的结构问题

- `EditorPanel` 同时包含主导航项和内部工作区项；`TEXT2` 以及模板子分类需要显式分类，避免枚举项被误认为全部同级。
- 弹窗状态散落为多个 Boolean/nullable State，返回逻辑容易遗漏新窗口；需要在阶段 E 迁移到统一窗口栈/弹窗注册表。
- 同一文件内有 AlertDialog、Dialog、DropdownMenu、复用输入弹窗等多种样式；标题字号、圆角、内容边距、按钮排列和关闭行为不统一。
- 颜色和尺寸常量在组件内重复出现；新版建立局部 UI tokens，先统一编辑器面板和弹窗，不覆盖文章 HTML 样式。
- 选区工具栏、底部面板、画布弹层之间有多个独立显示状态；需要明确互斥/共存规则和 zIndex。
- 部分快捷按钮直接写死 HTML/CSS，属于业务能力，应保留；UI 整理只调整它们的容器和分类。
- 图片裁切、调色和素材预览属于高风险路径，必须保留独立回调并回归，不可用通用表单替代专业窗口。
- 文字选区 Range 可能在焦点转移后失效；面板切换必须保存/恢复有效 Range，不可仅依赖 Compose 的 `selectedTextActive`。
- 画布浮层需要有界触摸区域，禁止全屏透明覆盖层阻断 WebView。
- 目前某些面板工具密集、标签短且图标映射基于文本关键词；需逐项检查图标唯一性、可读性和点击热区。

## 6. 全功能保留验收基线

- 旧版与新版的一级入口数量、二级功能项、弹窗入口、悬浮工具和数据动作逐项比对。
- 新版不得少于旧版任何可操作能力；如果重新归类，必须有明确的新入口映射。
- 每个工具需有可执行回调，不允许只留下无动作的展示项。
- 每个弹窗必须有关闭、确认、取消或恢复语义；专业窗口需要保留实时预览和错误反馈。
- 文字/图片/组件/表格/布局/多选对象分别测试选中、面板切换、编辑、撤销、返回和保存。
- 每一轮 CI 检查最终合成源码，不能只验证 overlay 脚本可提交。
