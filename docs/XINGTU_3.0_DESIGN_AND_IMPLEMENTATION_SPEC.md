# 醒图 3.0 界面、图标与交互设计规范

> 本文件是 `allsents` 仓库中醒图 3.0 的长期设计与实施基准。后续所有醒图 3.0 的界面改版、功能迁移、交互修复、代码重构和验收，必须先阅读并遵循本文件。若实现与本规范冲突，以本规范为准；若确需调整规范，先更新本文件并说明原因，再修改代码。
>
> 本规范只约束醒图 3.0。除非用户明确要求，不得借醒图 3.0 改造影响原醒图页面、秀米页面、普通排版页面或其他业务。

## 0. 总体目标与不可违反的原则

1. 醒图 3.0 是真正完成界面与交互升级的独立编辑器，不是仅复制旧页面、改标题或换入口。
2. 原醒图页面完整保留，不覆盖、不删除、不因 3.0 改造而改变其既有行为。
3. 3.0 必须保留原编辑器已经具备的成熟业务能力；重构分类和交互时不得随意删减功能。
4. 复用成熟业务逻辑、文章数据结构、WebView 编辑内核和 Bridge 兼容能力；UI、编辑会话、选中状态和面板状态按 3.0 的需要独立管理。
5. 文章数据、素材库、模板库可按统一数据模型共享；当前选中对象、打开的面板、临时编辑草稿、手势状态和撤销历史必须有清晰的编辑会话边界。
6. 所有编辑操作必须可理解、可预期、可撤销；画布是最终视觉结果的真实反映。
7. 先完成设计规范、代码改造和静态/逻辑检查，再统一构建 APK；除非用户另行要求，中途不为未完成阶段反复构建。
8. 不得把“代码已写入”“脚本已运行”表述为“功能已验收”。构建、运行和真机验证分别记录状态。

## 1. 页面整体结构

醒图 3.0 采用清晰的三段式编辑器结构：

- 顶部操作栏：返回、文章标题/文章信息、撤销、重做、预览、保存、更多。
- 中央文章画布：白色文章内容区域，负责真实内容呈现、对象选择、缩放、滚动和编辑反馈。
- 底部工具区：默认显示一级功能导航；选择对象或进入具体功能后，显示覆盖一级导航的非模态底部二级功能面板。

画布应尽可能占据可用空间，不增加无意义的外层卡片、重复边框或多层嵌套容器。画布与面板之间层级明确。

### 1.1 顶部操作栏

至少覆盖：
- 返回/退出编辑。
- 当前文章标题及必要的文章信息入口。
- 撤销、重做。
- 预览。
- 保存/保存状态。
- 更多操作（文章设置、导入导出等按场景组织）。

保存状态应明确区分保存中、已保存、失败/待重试。退出或切换文章时不得静默丢失未保存内容。

### 1.2 画布

- 画布显示的内容必须与当前编辑数据一致。
- 支持文字、图片、组件、表格、SVG、分栏/布局等对象。
- 支持对象选择、拖动、缩放（按对象能力）、滚动和合理的画布缩放。
- 选中对象应有清晰但克制的选中边界/控制点；控制点不能遮挡内容或阻止正常滚动。
- 画布操作与二级面板操作必须双向同步。
- 画布缩放、适应屏幕、参考线等工具归入画布/排版相关功能，不应混入无关分类。

## 2. 一级功能分类（目标结构）

统一为以下 8 个一级分类，职责不得交叉混乱：

| 一级分类 | 职责 | 主要内容 |
|---|---|---|
| 文字 | 文字内容与文字本身的属性 | 编辑文本、字体、字号、字重、字形、颜色、描边、渐变、阴影、透明度、字距、行距、段落、列表、查找替换、格式刷 |
| 图片 | 图片资源与图像处理 | 导入、替换、裁剪、旋转、翻转、调色、滤镜、抠图（若已有能力）、透明度、圆角、边框、阴影 |
| 组件 | 可插入的结构化内容对象 | 标题、引用、提示卡片、时间轴、表格、代码块、SVG、装饰组件及其他内容组件 |
| 排版 | 对象位置和空间关系 | 对齐、分栏、宽度、高度、间距、边距、缩放、位置、布局规则、参考线 |
| 图层 | 对象组织和层级管理 | 选择、排序、置顶/置底、上移/下移、显示/隐藏、锁定/解锁、多选、组合/取消组合、复制、删除 |
| 样式 | 对象外观与视觉表现 | 颜色、背景、边框、圆角、阴影、透明度及适用对象的整体外观 |
| 模板 | 可复用内容和设计 | 整篇模板、局部模板、组件模板、组合模板、收藏、分类、导入导出 |
| 文档 | 文章生命周期与文件管理 | 新建、打开、文章管理、保存、版本历史、导入导出、兼容性检查、文章信息 |

分类约束：
- 删除“文字2”作为独立一级导航的设计；其能力归入文字下的二级分组。
- 标题、卡片、表格、SVG 等作为可编辑对象统一归入组件；保留各自专属属性与编辑面板。
- “布局”不再作为对象类型与功能类别混用；位置、分栏和空间关系归入排版。
- “图文收藏”和“图文模板”统一整理到模板分类，但保留收藏与模板的不同语义。
- 同一个功能只设置一个主要归属；其他位置可提供快捷入口，但必须调用同一套实现，不能形成重复、分叉的状态逻辑。
- 原有功能逐项映射到新分类，迁移前建立清单，不能因分类调整而遗漏功能。

## 3. 二级功能面板规范

二级面板是实际编辑区域，一级导航只负责选择分类。

### 3.1 展示与尺寸
- 二级面板为非模态底部面板。
- 打开后覆盖一级导航栏；面板内部不得重复显示一级导航栏。
- 默认/最小高度 200dp，最大高度 400dp。
- 支持手势向上展开、向下收起；拖动区域明确，不能与面板内部滑动控件冲突。
- 面板内容可滚动；软键盘出现时应合理避让。
- 左侧关闭/取消，右侧确定/应用；无待提交事务的只读面板可按场景简化，但不得出现无效按钮。

### 3.2 实时预览与事务语义
- 打开面板时保存该次编辑的初始快照。
- 修改滑块、颜色、字号、输入值或选项时，画布立即预览。
- 点击确定：提交本次变更并形成一条合理的撤销记录。
- 点击取消/关闭：恢复打开面板前的状态。
- 快速连续调整同一属性时应合并为合理的一次撤销操作，避免撤销历史被滑块每一帧填满。
- 面板切换对象、切换分类、退出页面时，必须明确处理未提交事务，不允许状态串线。
- 画布直接拖动或操作时，面板中对应属性应同步更新；面板修改也必须即时反映到画布。
- 不得出现“点击确定才刷新画布”或“面板数值变化但画布不变”的情况。

### 3.3 交互可用性
- 面板内部控件必须可正常点击、拖动、输入和滚动。
- 关闭、确定、展开、收起等触控热区足够大。
- 不允许透明遮罩拦截面板内部操作。
- 面板打开时一级导航不应仍可误触。
- 面板高度、手势和画布滚动之间不得相互抢事件。

## 4. 统一对象模型与选择机制

所有画布内容应由统一的对象选择/操作入口管理，至少覆盖：
- 文字对象。
- 图片对象。
- 组件对象。
- 表格对象。
- SVG/矢量对象。
- 布局/分栏对象。
- 多选对象。

选择机制要求：
1. 选中对象后识别对象类型，自动展示相应工具，不展示无关功能。
2. 对象 ID 稳定且唯一，画布、图层列表、面板和数据模型使用同一对象身份。
3. 画布选中与图层列表选中双向同步。
4. 多选时提供适用的共同属性操作；不适用的属性明确禁用，不得错误地修改部分对象。
5. 删除、复制、移动、锁定、组合等操作必须作用于当前选中对象。
6. 选中边框、控制点和拖动手柄不得破坏正文点击、文本选择和画布滚动。
7. 对象类型不支持的能力不显示或明确禁用，不允许出现点击无效的入口。

## 5. 图片编辑规范

图片选中后提供一致的图片工具组织：

- 编辑：裁剪、旋转、翻转、替换。
- 调色：亮度、对比度、饱和度、色温、色调等已支持参数。
- 样式：圆角、边框、阴影、透明度。
- 排版：宽度、高度、对齐、位置、间距。
- 图层：顺序、锁定、复制、删除。

要求：
- 图片导入必须可用，支持现有业务支持的导入来源。
- 裁剪和调色不得导致应用崩溃。
- 裁剪、调色、旋转、翻转等变更应实时反映到画布。
- 取消操作恢复初始图像状态；确定操作提交并可撤销。
- 图片替换后应保留适用的布局属性；不适用的裁剪参数应安全重置。
- 图片素材应考虑文章、模板和历史版本的引用关系；删除文章不得误删仍被其他内容引用的素材。
- 不得因 3.0 改造破坏原有图片处理内核或兼容能力。

## 6. 图层规范

图层至少支持：
- 选中、上移、下移、置顶、置底。
- 显示、隐藏。
- 锁定、解锁。
- 复制、删除。
- 多选。
- 组合、取消组合。

画布对象和图层列表必须保持一一对应。图层排序变更应立即反映到画布；画布对象变化也应更新图层列表。锁定对象不能被误拖动或误编辑；隐藏对象不参与普通画布命中选择，但仍可从图层面板重新显示。

## 7. 图标设计规范

### 7.1 总体风格
- 采用极简线性图标为主，必要时少量线面结合用于重点状态。
- 统一使用 Lucide 风格的 SVG 矢量图标或自绘同风格 SVG。
- 线条圆润、端点和转角统一，保持小尺寸下的辨识度。
- 禁止使用 Emoji、随意字符、文本符号或不一致的系统图标拼凑正式功能图标。
- 不允许同一功能在不同页面使用不同含义的图标。
- 不为了追求极简而牺牲语义辨识度。

### 7.2 尺寸与线宽
| 场景 | 建议图标尺寸 | 参考线宽 |
|---|---:|---:|
| 顶部操作栏 | 20–22px | 2px |
| 一级导航 | 23–25px | 2px |
| 二级面板 | 21–23px | 2px |
| 小型工具按钮 | 18–20px | 1.8px |
| 弹窗操作 | 20px | 2px |
| 画布浮动工具 | 18–22px | 2px |

- 图标与文字间距建议 5–7px。
- 点击热区建议至少 44×44dp；图形本身可以更小。
- 实际尺寸应考虑 Android density 与布局组件，避免把 px 和 dp 混用。

### 7.3 颜色与状态
- 默认状态使用主题前景色。
- 选中状态使用主题强调色，可配浅色背景。
- 禁用状态降低对比度，但仍保持可辨认。
- 深色/浅色主题自动适配。
- 同一组图标的线宽、视觉重心、留白和对齐保持一致。

### 7.4 图标库分类
图标库至少覆盖：
- 顶部操作：返回、撤销、重做、保存、预览、更多、历史、设置。
- 一级导航：文字、图片、组件、排版、图层、样式、模板、文档。
- 文字：字体、字号、粗体、斜体、下划线、删除线、颜色、背景、行距、字距、对齐、列表、描边、渐变、阴影。
- 图片：导入、替换、裁剪、旋转、翻转、调色、透明度、圆角、边框、阴影、滤镜、抠图（仅在能力真实存在时展示）。
- 组件/排版：标题、卡片、引用、表格、分栏、间距、对齐、组合。
- 图层：置顶、置底、锁定、隐藏、多选、复制、删除。
- 模板/文档：收藏、搜索、分类、导入、导出、复制、删除、分享。
- 画布：缩放、适应屏幕、参考线、选择、拖动、变换锚点。

### 7.5 图标技术实现
- 建立统一图标资源目录/注册表，以稳定的 icon ID 映射 SVG/vector drawable。
- 组件只引用 icon ID，不自行拼字符或临时画符号。
- 主题颜色由统一 tint/theme token 控制，图标资源不硬编码页面颜色。
- 现有通过文字匹配生成符号的 `editorToolGlyph()` 等实现应逐步替换为明确的图标 ID 映射。
- 每个 icon ID 有明确语义；同一图标可在多处复用，但不允许不相关功能共用图标。
- 对通用图标库没有覆盖的专用编辑功能，绘制专用 SVG，并纳入同一资源规范。
- 引入图标前检查许可证、资源体积、命名冲突和深浅主题可读性。

## 8. 视觉与布局规范

- 延续应用整体简洁风格，不做无必要的大面积底纹和装饰。
- 避免“矩形里面再套矩形”的多层卡片。
- 控件、面板、按钮、输入框和弹窗使用统一圆角、间距、边框和状态规范。
- 视觉层级依靠排版、留白、字重和少量强调色建立，不依赖大量阴影。
- 面板内容优先按任务分组，常用功能优先，低频高级功能收纳到次级区域。
- 同一类属性使用相同控件模式；数值滑块、颜色选择、输入框和开关的行为一致。
- 不得只为了截图好看而牺牲实际点击区域和编辑效率。

## 9. 文章、编辑会话与数据逻辑

### 9.1 文章上下文
- 使用稳定的文章 ID。
- 从文章列表进入时打开指定文章。
- 从排版页新建时创建新文章或允许选择已有文章。
- 从原醒图跳转 3.0 时，明确传递当前文章 ID 和必要的文章上下文；不得无提示地另建“未命名文章”导致用户以为继续编辑原文。
- 返回、切换编辑器或退出时保存/提示未保存修改。

### 9.2 状态隔离与共享
可共享：
- 文章持久化数据模型。
- 素材库。
- 模板库。
- 文章资源引用。

必须按编辑会话隔离或明确归属：
- 当前选中对象。
- 当前打开的一级分类和二级面板。
- 临时编辑快照。
- 面板展开高度与手势状态。
- 当前画布临时交互状态。
- 撤销/重做历史（除非明确设计为同一文章跨编辑器共享，并有一致性保障）。

### 9.3 撤销与重做
- 文字、图片、组件、布局、图层、插入、删除等重要操作纳入历史。
- 连续滑块操作应合并成合理事务。
- 面板取消不应留下已提交历史记录。
- 撤销/重做后画布、面板、图层列表和文章数据保持一致。
- 异步图片操作和导入操作需要定义成功、失败及撤销行为。

### 9.4 保存与资源
- 保存状态可见。
- 保存失败可重试，不得静默丢失。
- 同一文章被多个编辑器打开时，需防止旧草稿覆盖新数据。
- 图片资源采用引用安全策略；仅在确认无文章、模板、历史版本引用时才允许清理。
- 导入导出应保留文章结构、图片资源和必要元数据。

## 10. 原有功能迁移与兼容

- 先盘点原醒图所有一级入口、二级功能、操作行为和数据字段。
- 建立“原功能 → 3.0 新分类 → 实现位置 → 验收状态”的迁移表。
- 迁移时优先复用已验证的业务逻辑，不为改 UI 重写成熟内核。
- 保留 WebView 编辑内核及既有 Bridge 接口的兼容行为，除非经过专项验证后有计划地替换。
- 对原有崩溃修复、裁剪/调色、实时同步等历史修复进行回归验证。
- 原醒图路由和页面保持原样；秀米与普通排版页面不得被修改。
- 排版页新增的 3.0 入口只负责进入新编辑器，不应改变原醒图和秀米入口的行为。

| H | 视觉精修与完整验收 | 深浅主题、尺寸、触控、回归测试通过 |

阶段状态只能使用：未开始、进行中、代码完成待检查、检查通过、构建通过、真机验收通过、阻塞。未验收不得标记为完成。

## 12. 每次代码修改的强制工作流程

每次开始醒图 3.0 修改前：
1. 阅读本规范及当前阶段状态。
2. 检查目标分支最新代码，不依赖过期文件快照。
3. 明确本次只处理的阶段/问题、目标文件和预期行为。
4. 列出不得修改的边界：原醒图、秀米、普通排版及无关业务。
5. 确认功能迁移不会造成能力删减。

每次修改后：
1. 检查 diff，确认只改了计划范围。
2. 检查编译/API/资源引用和路由。
3. 检查画布、面板、对象状态和数据一致性。
4. 更新本规范中的阶段状态或关联的进度清单。
5. 记录未解决问题、风险和下一步。
6. 只有用户要求或核心改造完成后才构建 APK；构建成功也不等于真机验收成功。
