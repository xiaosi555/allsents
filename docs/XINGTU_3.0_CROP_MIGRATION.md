# 醒图 3.0 图片裁剪迁移说明

## 目标
将 `xiaosi555/photo` 安卓版的裁剪能力移植到 `allsents` 的独立醒图 3.0 编辑器「图片 → 裁剪」二级面板。只扩展醒图 3.0，不修改原醒图、秀米、普通排版及 photo 源项目。

## 来源实现
- `android/app/src/main/java/com/taoo/xiutu/tools/crop/Crop.kt`
  - `CropAspect`、`CropRect`、`CropParams`、`CropOp`
  - 旋转/翻转/拉直矩阵与最终像素裁剪
- `android/app/src/main/java/com/taoo/xiutu/tools/crop/CropSession.kt`
  - 裁剪框绘制、框外压暗、三分辅助线、四角控制点
  - 拖动/缩放手势、比例锁定、旋转、翻转、拉直与重置面板

## 目标功能
1. 比例：自由、原始、1:1、3:4、4:3、9:16、16:9、2:3、3:2。
2. 画布：图像完整预览；框外压暗；三分线；四角与边缘控制点。
3. 手势：移动裁剪框、拖动边/角调整范围；固定比例时保持比例；限制在图像边界内。
4. 变换：顺时针 90°、水平翻转、垂直翻转、-30° 至 +30° 拉直。
5. 操作：重置、取消回滚、确认应用；裁剪结果生成新的本地素材资源，不覆盖原始素材。
6. 状态：预览即时更新；确认后替换当前选中图片并写入撤销历史；取消恢复进入裁剪前的画布状态。

## 移植边界与适配
- 不直接复制 `CropSession : ToolSession(EditorModel)` 的上层会话依赖，因为 photo 的 `EditorModel/ToolSession` 与 allsents 的 WebView + Compose Bridge 编辑器并非同一状态模型。
- 保留并移植 `CropParams` 的矩阵/像素处理算法；将 `CropSession.Canvas/Panel` 改造成醒图 3.0 独立 Compose 裁剪视图，输入当前选中图片 Bitmap 与裁剪状态。
- 图片来源必须解析当前选中图片对应的本地 `MediaAsset`；远程图片/非本地资源应明确提示，不得伪装成可导出像素裁剪。
- 结果保存到文章素材目录，创建新 `MediaAsset`，通过现有图片替换 Bridge 更新画布。
- 裁剪面板沿用醒图 3.0 现有非模态底部面板规则（200–400dp）；不新增独立 Activity，不破坏 8 个一级分类。
- 继续使用项目已有的对象选择、保存、撤销/重做机制，避免另建一套互不一致的历史状态。

## 实施顺序
- CROP-A：移植纯裁剪数据模型与像素算法，适配包名、EditOp 依赖和高分辨率内存保护。
- CROP-B：实现独立 Compose 裁剪画布和交互（比例、边/角拖动、旋转、翻转、拉直、重置）。
- CROP-C：接入醒图 3.0 图片 → 裁剪面板、当前选中图片与本地素材解析。
- CROP-D：确认/取消事务、生成新素材、替换画布图片、撤销重做与历史状态同步。
- CROP-E：自动化静态检查、Kotlin 编译、APK 构建；设备验收裁剪手势、方向、比例、原图保留和取消回滚。

## 验收约束
- 不得把代码复制或 Kotlin 编译通过当作功能验收。
- 必须检查 EXIF 方向、高分辨率图片、边界裁剪、极窄/极宽比例、旋转后比例、翻转后坐标、连续拖动、取消与撤销。
- 未完成设备验证前，状态只能标记为代码完成待检查或构建通过，不得标记真机验收通过。
