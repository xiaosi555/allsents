## 阶段 A/B 本轮实现记录（2026-11-29）

### 阶段 A：文章上下文与编辑会话
- 3.0 Composable 增加可选 `initialArticleId` 参数；当前排版页通用入口不传 ID 时，优先恢复 3.0 自己上次打开的文章，否则创建新草稿。
- 文章首次进入时恢复标题、HTML、subtitle、summary、author、category、tags、status、coverAssetId。
- 新建文章、打开文章都会更新 `xingtu_v3_editor_session` 中的 `active_article_id`；此偏好与原醒图编辑器隔离。
- 路由 ID 在同一 Compose 宿主变化时，先保存当前文章，再打开目标文章。
- 原醒图的 ArticleEditorScreen、秀米、普通排版没有被本轮业务代码修改。
- 文章和素材持久化数据仍复用 AppViewModel；3.0 当前选中面板、对象、弹窗、手势等状态留在独立 V3 Composable 内。

### 阶段 B：8 类一级导航
- 主导航固定为：文字、图片、组件、排版、图层、样式、模板、文档。
- 文字：基础/高级（旧 TEXT/TEXT2）。
- 组件：标题、卡片、组件、SVG；表格等原有组件能力仍保留在组件面板。
- 排版：分栏、画布设置；画布设置使用同一底部二级面板。
- 样式：新增统一外观入口，调用现有模块属性、文字样式、图片样式面板。
- 模板：模板库与收藏两个子页；旧收藏分支不删除，只从一级导航移入模板。
- 原有 EditorPanel 功能分支保留，导航重组通过新 EditorCategory 映射，不通过删除旧面板实现。
- 3.0 生成补丁已通过 GitHub Actions 的 Stage A/B 脚本步骤；当前 Kotlin compile-only 检查仍在运行，未据此标记为检查通过。

### 构建控制
- APK 工作流已改为仅手动触发（workflow_dispatch），阶段 A/B 和后续阶段未验收前不自动构建 APK。
- 本轮只运行 Kotlin compile-only 检查；没有主动触发 APK 构建。

## 已确认的主要问题

- 旧一级枚举有 13 项，与目标 8 类结构不符；模板子导航还重复包含图片/布局/组件等类别。
- 二级面板当前最小高度可到 100dp，普通面板默认 180dp，不符合 200–400dp 规范。
- 当前确定/关闭入口未体现统一编辑快照和取消恢复事务。
- 工具图标由 editorToolGlyph(label) 返回字符，不符合正式矢量图标库规范。
- 编辑器初始 articleId 由 vm.newId() 生成；路由没有显式文章上下文参数，需解决新建/打开/继续编辑的语义。
- Bridge 明确处理文字、图片、模块选择；更多对象类型的统一身份与同步仍需核实。
- 现有 WebView 内核、素材库、模板、文章导入导出、版本记录等必须保留，不能为重做 UI 而删减。
