# 文章编辑器交互与功能架构技术方案

> 项目：拾万句 APP  
> 适用范围：Android 原生界面 + WebView 图文编辑画布  
> 方案阶段：交互与技术方案先行；本文件确认前不进入 UI 改版和功能实现  
> 参考对象：秀米图文编辑器的功能组织与交互逻辑；醒图画布编辑的直接操作感  
> 约束：保留现有文章编辑器全部有效功能、数据结构、导入导出能力和文章内容兼容性

## 1. 目标与边界

本轮先解决“功能放在哪里、何时出现、如何操作、如何与画布状态联动”，不先改视觉皮肤。

最终交互原则：

1. 文章画布是中心，用户点击画布中的文字、图片、组件或布局，系统识别当前对象类型。
2. 底部功能栏始终固定显示，不因选中文字或图片而消失。
3. 只有与当前对象有关的快捷操作才以悬浮工具窗出现；悬浮窗不承担所有功能入口。
4. 模板素材、收藏、图库、剪贴板、文档管理等“主动添加/管理”功能放在固定入口及其内容面板中。
5. UI 第二阶段才调整；继续沿用 APP 当前排版页的画布、颜色、圆角、间距和整体样式体系，不照搬秀米网页端的左右栏布局，也不把醒图的视觉皮肤直接搬进来。
6. 功能必须真实可用。每个按钮都必须关联明确的编辑命令、数据操作或页面动作；不允许只做图标占位。

## 2. 秀米功能体系与交互规律（公开资料归纳）

秀米公开教程呈现出“素材区 + 编辑画布 + 对象工具条 + 全文/文档操作”的组合，而不是把所有操作堆在同一个工具栏里。

### 2.1 素材与模板区

常见入口/分类包括：

- 图文模板：标题、卡片、图片、布局，以及 SVG/互动、组件等扩展分类。
- 图文收藏：将已经调整过的单个模块或多个模块保存起来，供其他文章重复插入。
- 剪贴板：临时保存复制的模块；与长期收藏的用途不同。
- 我的图库：上传、浏览、搜索、替换图片。
- 模板可通过点击插入，也可拖动到画布；插入位置会受当前选中模块或光标位置影响。
- 选中文字后插入标题模板等内容时，可将选区转化为对应结构；光标定位后插入内容时，可在该位置分段插入。

对拾万句的启示：模板/收藏/图库属于“素材供给与管理”，应该是固定功能入口打开的面板，不应该在每次点击画布文字时自动弹出。

### 2.2 选中对象后出现的工具条

秀米教程明确描述：选中编辑区元素后会出现基础工具条和对象属性工具条；对象属性工具条根据选中的是文字、图片还是布局而变化。

- 基础工具条：复制、收藏、删除、插入空行、更多操作、定位等，主要作用于当前模块。
- 文字工具条：选中文字或文字模块后出现，提供文字格式相关设置。
- 图片工具条：选中图片后出现，提供宽度、裁剪、边框、阴影等图片属性。
- 布局工具条：选中布局后出现，提供布局宽度、背景、边框、阴影、列/行调整、滑动序列等结构属性。
- 多选时出现针对多个模块的操作，例如复制、收藏、删除、移动；跨布局选择可能受到限制。
- 秀米手机版教程也采用单击选中、再点击进入文字编辑等分层操作；底部提供新增文字/图片入口，选中对象后属性工具条切换为相应类型。

对拾万句的启示：悬浮工具窗应当是“上下文工具”，由当前选中对象决定内容，而不是固定展示一套图片和文字混合按钮。

### 2.3 全文级与文档级功能

以下功能不是对单个文字或图片即时操作，通常应放在固定区域、顶部操作或独立面板：

- 全文基础格式：基础字号、字体、行距、字间距、段落间距、页边距、正文颜色、背景。
- 文章信息：标题、摘要、作者、封面等。
- 保存、预览、导出/同步等文章级操作。
- 搜索、替换、历史版本、兼容性检查等管理工具。

对拾万句的启示：不能把全文设置放进文字悬浮窗，否则用户容易误以为只影响当前选中文字。

### 2.4 公开资料的边界

公开教程能证明秀米对外呈现的操作方式、工具分类和功能用途，但不能据此断言秀米内部使用了哪一种 DOM 框架、编辑器内核或私有算法。本方案只借鉴可观察到的交互规律；具体技术选型以拾万句现有代码为基础。

## 3. 功能出现位置与触发时机

| 功能类别 | 固定入口/位置 | 触发悬浮窗口的时机 | 主要操作 |
|---|---|---|---|
| 文字 | 底部“文字”入口 | 点击画布文字模块；或长按/拖选文字形成有效选区 | 字号、字体、颜色、加粗、斜体、下划线、删除线、对齐、列表、格式刷等 |
| 图片 | 底部“图片”入口 | 点击画布图片 | 宽度/尺寸、裁切、旋转、圆角、边框、阴影/透明度、替换、说明、删除 |
| 组件 | 底部“组件”入口 | 点击已插入的组件/模块 | 组件替换、复制、删除、上下移动、间距/背景/边框等组件属性 |
| 图层/布局 | 底部“图层”入口 | 点击布局容器、表格或组合结构 | 层级、宽度、列/行、对齐、间距、背景、边框、滑动布局等 |
| 图文模板 | 底部固定入口 | 用户主动点击 | 标题、卡片、图片、布局等模板分类；搜索、预览、插入 |
| 图文收藏 | 底部固定入口 | 用户主动点击；或在对象工具窗中点“收藏”后更新 | 收藏列表、分类筛选、搜索、插入、取消收藏 |
| 文档 | 底部固定入口或顶部文档操作区 | 用户主动点击 | 文章信息、全文基础格式、查找替换、历史版本、导入导出、预览等 |
| 基础模块操作 | 对象悬浮窗中的“更多”分组 | 选中对象后 | 复制、收藏、删除、前插/后插空行、移动、链接等 |

### 3.1 文字悬浮工具窗

出现条件：
- 点击正文中的文字模块，进入“文字对象选中”状态。
- 长按/拖动选择部分文字时，进入“文字选区”状态；若当前有实际选区，格式操作作用于选区。
- 仅有光标没有选区时，字号/字体/颜色等格式操作作用于当前段落或后续输入状态，不能误报为“已修改选中文字”。

建议分组：
1. 字体：字号下拉、字体下拉、颜色下拉。
2. 字形：加粗、斜体、下划线、删除线、上标、下标、清除格式。
3. 段落：左/中/右对齐、行距、首行缩进、段前段后距。
4. 结构：标题级别、正文、引用、无序/有序列表、缩进。
5. 效率：格式刷提取/应用、复制文字、查找替换入口。
6. 更多：分段、链接、删除文字模块、复制模块、收藏模块。

交互细节：
- 字号、字体、颜色采用“图标 + 当前值 + 下拉三角”，点击后弹出轻量选择菜单。
- 加粗/斜体/下划线/删除线采用图标按钮，并提供选中态反馈。
- 点击悬浮窗时必须保存并恢复编辑器真实 Selection/Range，避免焦点切换后选区丢失。
- 文字选区与文字模块选中是两种不同状态；模块级操作不能错误地只作用于几个字符。

### 3.2 图片悬浮工具窗

出现条件：点击画布中的图片，且该图片成为唯一活动图片。

建议分组：
1. 尺寸：宽度预设、百分比/数值输入、适配画布。
2. 裁切：常用比例、自定义裁切、重置裁切。
3. 变换：旋转、必要时镜像/翻转。
4. 外观：圆角、边框、阴影、透明度。
5. 内容：替换图片、图片说明/替代文本、链接。
6. 操作：复制、收藏、删除、前后移动。

重要实现要求：
- “裁切”不能只改变图片显示高度并设置 object-fit 就宣称完成了像素裁切。应明确区分“显示裁切（非破坏性）”与“生成裁切副本（像素裁切）”。
- 对本地素材，像素裁切生成新素材文件并更新文章引用；原素材默认保留，避免破坏其他文章/模板的引用。
- 对外链或不受控来源图片，若不能读取原始像素，应禁用像素裁切并明确提示；仍可提供可逆的显示裁切。
- 图片替换、裁切、旋转、删除后必须更新 HTML、历史记录和保存状态。

### 3.3 组件/布局悬浮工具窗

组件和布局不能完全等同于普通文字或图片。选中表格、卡片容器、分栏/组合布局时，应识别其结构类型并展示不同属性。

- 普通组件：复制、替换、收藏、删除、上下移动、背景、边框、圆角、内边距。
- 表格：增加/删除行列、单元格样式、边框、对齐。
- 分栏布局：列数、列宽、列间距、内容对齐、列内插入。
- 滑动布局：滑动方向、序列项管理、容器高度、间距。
- 多选模块：统一移动、复制、收藏、删除；如果选中对象跨越不同布局，按安全规则限制不支持的操作并给出提示。

## 4. 推荐的拾万句页面结构

### 4.1 固定区域

- 顶部：返回、文章标题/保存状态、撤销/重做、预览/更多文档操作（沿用现有顶部结构，不在本阶段重新设计皮肤）。
- 中部：文章画布。保留当前排版页的画布宽度、纸张/内容区、背景和滚动逻辑。
- 底部：固定功能栏，始终可见。入口建议为：文字、图片、组件、图层、图文模板、图文收藏、文档。
- 点底部入口时，在底部栏上方展开对应工具面板；面板可滚动，但底部主入口不消失。

### 4.2 悬浮窗口

- 用户点击画布文字/图片/组件/布局时，在画布上层出现对应的上下文悬浮工具窗。
- 悬浮窗与底部主功能栏是两层不同职责：底部栏负责“我要做什么类别的事”；悬浮窗负责“我当前选中的这个对象能做什么”。
- 悬浮窗默认靠近选中对象，但不得遮挡对象的主要编辑区域；空间不足时自动移到对象上方/下方，必要时固定在画布底部栏上方。
- 悬浮窗不能遮挡系统键盘、系统导航区或顶部保存操作。
- 点画布空白处、点“完成”或切换到不相关对象时，按规则关闭/切换悬浮窗；不能在用户正在编辑文字时因为误触空白区域丢失选区。

### 4.3 模板与收藏

“图文模板”和“图文收藏”作为两个独立固定入口：
- 图文模板：标题、卡片、图片、布局、组件/互动等类型；支持搜索、预览、插入。
- 图文收藏：统一管理用户收藏的标题、卡片、图片、布局和组合模块；支持分类筛选、搜索、插入、取消收藏。
- 对象悬浮窗的“收藏”动作保存当前选中模块或多选组合；收藏数据应持久化，应用重启后仍存在。
- 模板分类必须优先使用稳定的 categoryId/type/tag 等结构化元数据；不能只靠模板名称关键词猜分类，否则会出现分类漏项或空分类。

## 5. 当前代码基础与技术可行性

根据当前 main 分支的 ArticleEditorScreen.kt，编辑器并非从零开始：
- Android 界面由 Jetpack Compose 组织，正文画布嵌入 Android WebView。
- WebView 内部使用 contenteditable 编辑区域和 JavaScript 处理选中、插入、图片、模块拖动、历史记录等。
- Compose 通过 AndroidView 承载 WebView，并通过 ArticleEditorBridge 回传内容变化、模块选中、图片选中和文字选中状态。
- JavaScript 侧已有 savedRange/restoreSelection、文字样式、图片尺寸/旋转/裁切、模块复制删除、表格增减行列、多选拖动等逻辑。
- 原生侧已有本地图片导入、替换、像素裁切、模板包/文章包导入导出、文章保存和版本相关功能。

因此，第一阶段不建议立即重写编辑器内核。优先在现有 WebView + Compose 架构上补齐“选中状态模型、悬浮窗定位、命令路由、功能盘点与验收”，风险和回归成本更低。

### 5.1 选中状态模型

建议统一成明确状态，而不是依赖多个布尔值互相推断：

- None：没有选中对象。
- TextBlock：选中整个文字模块。
- TextRange：存在有效文字选区。
- Image：选中一张图片。
- Component：选中普通组件。
- Layout：选中布局/表格/容器。
- MultiBlock：选中多个模块。
- Editing：文字输入/键盘编辑中（可同时保存当前对象上下文）。

每个状态至少包含：对象类型、稳定对象标识、选区是否折叠、选中 HTML/节点信息、画布坐标、是否正在输入、当前文档版本。

### 5.2 WebView 与 Compose 的职责

WebView/JavaScript 负责：
- 识别 DOM 选中对象、文字 Range、图片与布局节点。
- 执行 DOM/HTML 编辑命令。
- 计算选区或对象的 getBoundingClientRect()。
- 保存/恢复 Selection/Range。
- 提交编辑历史并回传内容变化。

Compose 负责：
- 固定底部主功能栏、工具分类面板。
- 依据选中状态展示文字/图片/组件/布局悬浮窗。
- 处理悬浮窗的避让、边界限制、下拉菜单和系统窗口适配。
- 处理本地文件选择、像素裁切、文章/模板数据持久化等原生能力。

两端通过窄接口传递结构化事件，不让 Compose 直接拼接复杂 DOM 操作，也不让 WebView 自行管理整套原生工具面板。

### 5.3 文字选区技术

- 使用浏览器 Selection API / Range 读取真实选区、光标位置和边界矩形。
- 在用户选择文字、点击文字工具、WebView 失焦、软键盘弹出等时机同步选区状态。
- 用户点击 Compose 悬浮窗后，先恢复 Range，再执行格式命令；执行后重新保存 Range 并记录历史。
- 当前代码仍使用部分 document.execCommand。该接口已不适合作为长期编辑内核的唯一基础；短期可以保留已验证的命令以降低回归风险，逐步把关键格式操作迁移为 Range/DOM 操作，并为每项命令建立测试。
- applyInlineStyle 需要处理跨多个节点、已有嵌套 span、跨段落选区、空选区、撤销/重做和格式清除，不能只覆盖单一文本节点的简单情况。
- 字体选项应展示设备/导出环境的兼容性说明；不同 Android 字体可用性和微信公众号端字体渲染不完全一致。

### 5.4 图片与裁切技术

- 选中图片时为 DOM 图片建立稳定 ID，不能只依赖图片 outerHTML 字符串定位目标。
- 显示宽度、圆角、边框、阴影、透明度、object-position 等作为非破坏性样式属性保存。
- 显示裁切使用容器 + object-fit: cover / object-position，并保存原始样式和裁切参数。
- 像素裁切使用原生 Bitmap 处理本地素材，生成新的 MediaAsset，再把文章图片 src 指向新资源；不得覆盖被其他内容引用的原图。
- GIF/WebP/HEIC 等格式需分别测试；不支持像素裁切的格式要提示并提供显示裁切替代方式。
- 图片变换应写入统一历史记录，撤销后恢复图片尺寸、比例、位置及资源引用。

### 5.5 悬浮窗定位

- JavaScript 回传对象/选区在 WebView 内容坐标中的矩形。
- Compose 根据 WebView 在屏幕中的位置、滚动偏移、缩放比例和系统 Insets 转换坐标。
- 工具窗根据矩形自动选择上方或下方位置，并限制在可视窗口范围内。
- 页面滚动、软键盘出现、窗口尺寸变化、横竖屏切换时重新计算位置。
- 如果坐标映射在某些设备上不稳定，先采用“固定在画布底部栏上方”的稳定方案，不能让悬浮窗错位或挡住输入区域。

### 5.6 安全与兼容

- 当前 WebView 使用本地 editor.local 资源拦截与 HTML 清理逻辑，应继续保持编辑画布只加载受控内容。
- 不允许加载不可信远程 HTML 后仍暴露可调用任意原生能力的 JavaScript bridge。
- Bridge 仅开放必要回调；对输入字符串、资源 ID、文件路径进行校验。
- 导入 HTML/模板/文章包继续经过现有清理与大小限制，不因新增模板或悬浮窗而绕过安全处理。
- 文章原有 HTML、图片资源 ID、模板数据、版本快照和导入导出格式必须向后兼容。

## 6. 现有功能保护与实施顺序

### 阶段 A：功能盘点（不改 UI）

逐项读取当前 ArticleEditorScreen.kt、ViewModel、数据模型、HTML 清理/导入导出逻辑，形成“现有功能 → 新入口 → 实际处理函数 → 数据影响 → 验收方式”清单。所有现有功能必须有归属；不确定是否可用的功能先标记待验收，不可直接删除。

### 阶段 B：交互底座

1. 建立统一选中状态模型。
2. 将文字模块、文字选区、图片、组件、布局、多选区分。
3. 让 WebView 回传稳定对象 ID、选区状态和坐标。
4. 建立命令路由和统一历史记录入口。
5. 先测试选中/取消选中、光标恢复、撤销重做和保存。

### 阶段 C：功能入口与悬浮窗

1. 底部固定栏保持常驻。
2. 文字悬浮窗按状态显示文字格式功能。
3. 图片悬浮窗按状态显示图片功能。
4. 组件/布局/多选悬浮窗显示对应功能。
5. 模板与收藏独立面板，完成分类、搜索、预览、插入和收藏持久化。

### 阶段 D：验收后再做 UI

只有交互和功能测试通过后，才进行视觉优化：
- 以现有排版页为样式基准。
- 底部功能栏常驻。
- 悬浮窗采用轻量图标化分组。
- 字号、字体、颜色保留文字与下拉三角提示。
- 不随意改变画布尺寸、文章内容宽度、主题色、圆角、间距和整体布局。
- 不做无关的整体重绘。

## 9. 本阶段结论

方案可行，建议在现有 Compose + WebView 编辑器上渐进实施，不先整体替换编辑器内核。

关键调整不是“再增加几个按钮”，而是把编辑器明确分为三层：
1. 固定功能入口：用户主动选择要添加或管理的功能类别。
2. 画布对象选择：识别文字、图片、组件、布局和多选状态。
3. 上下文悬浮工具窗：只显示当前对象可执行的属性和操作。

本文件是交互与技术方案，不代表功能已经实现或验收通过。下一步应先完成现有功能全量盘点和命令映射表，再按阶段 B、C 实现；阶段 D 才做视觉样式优化。

## 9. v2 交互重构：默认底栏与对象上下文底栏（2026-11-27）

> 本节覆盖旧方案中“选中对象后以悬浮工具窗作为主要操作入口”的设计。新方案以本节为准；悬浮窗只保留为可主动打开的对象快捷工具，不再承担主要属性入口。

### 9.1 导航状态机

底部同一位置只显示一套导航栏，依据画布当前状态切换：

| 状态 | 底部导航 |
|---|---|
| 无对象选中 | 加图、加字、图文模板、图文收藏、文档、画布、图层 |
| 文字对象选中 | 编辑、字体、样式、排版、透明度、存为模板、顺序、对齐、创建副本、复制、复制样式、粘贴、多选、锁定 |
| 图片对象选中 | 替换、裁剪、调色、透明度、边框、圆角、阴影、翻转、对齐、复制、复制样式、粘贴、设为背景图 |
| 组件/布局对象选中 | 组件属性、顺序/移动、对齐、复制、复制样式、粘贴、存为模板、多选、锁定/解锁、删除；表格和布局继续显示专属行列/结构操作 |

点击画布空白区域或明确执行“完成/取消选择”后恢复默认导航。切换对象类型时，必须在同一底栏位置替换内容，不允许同时叠加两条底部栏。

默认底栏行为：
- 加图：启动系统图片选择器，导入后在当前光标/选中位置插入图片。
- 加字：建立新文字段落并主动请求软键盘。
- 图文模板：打开现有模板库。
- 图文收藏：打开收藏模板库；文字/图片/组件的“存为模板”必须写入同一持久化收藏数据。
- 文档：文章列表、文章信息、保存、版本、导入/导出、兼容检查等文章级功能。
- 画布：画布级属性与设置。
- 图层：图层列表、可见性、锁定、层级选择与排序。

### 9.2 文字对象交互

- 第一次点击文字：只选中整个文字段落/文字对象，不打开键盘。
- 对同一文字对象再次点击，或点击文字底栏“编辑”：进入编辑状态并请求系统输入法。
- 第一次选中后底栏切换为文字工具栏。
- “字体、样式、排版、透明度”均路由到现有文字2样式编辑能力。文字2二级导航扩展为四项：字体、样式、排版、透明度；点击任一入口时先打开文字2面板，再将对应 tab 设为当前项，不允许总是回到“字体”。
- “对齐”打开左对齐、居中、右对齐、两端对齐的明确选项；操作对象为当前文字段落，不得误改整个文档。
- “创建副本”复制当前文字段落并紧接在其后插入；原有下一段落顺延，不覆盖内容。
- “复制”复制当前选中段落/文字对象；“复制样式”读取当前文字样式；“粘贴”根据最近一次复制类型执行内容粘贴或样式粘贴，并保留真实 Selection/Range。
- “存为模板”保存当前文字模块 HTML 与类型元数据，收藏列表重启后仍可见。
- “顺序”进入对象顺序/组件移动模式；不得把 DOM 的临时选中态当成永久顺序数据。
- “多选”开启/退出现有多选模式；仅对明确选中的对象执行批量命令。
- “锁定”锁定对象位置与内容编辑；对象仍可被选中以显示组件工具，但不可拖动或修改内容。解锁入口必须可用。

### 9.3 图片对象交互

图片底栏每项都必须有真实操作，不允许只显示按钮：
- 替换：复用现有图片选择器和 replaceSelectedImage，保留图片原有对象 ID、替代文本和可恢复历史。
- 裁剪：同时提供可逆显示裁切与现有像素裁切；界面明确标注两者区别。重置裁切可恢复原始显示状态。
- 调色：新增可调亮度、对比度、饱和度、色温/色调或灰度等滤镜参数；参数保存为 CSS filter 或等效样式，并支持撤销/重做。
- 透明度：新增 0–100% 图片 opacity 调整。
- 边框：设置颜色、宽度、样式，提供无边框/预设。
- 圆角：提供常用预设及数值设置。
- 阴影：提供无/轻/中/强预设及可调整参数。
- 翻转：水平/垂直翻转，必须与旋转变换合并管理，不能覆盖已有旋转或 CSS transform。
- 对齐：左、中、右对齐；若图片位于分栏/表格单元格中，限制在当前容器内对齐。
- 复制：复制图片对象及其引用，不复制/覆盖原始素材文件。
- 复制样式：读取图片显示样式；粘贴时只应用样式，不替换图片资源。
- 粘贴：区分图片对象复制与图片样式复制。
- 设为背景图：将图片设为当前选中容器/画布背景；必须保留原图资源引用，并提供清除/替换背景入口。

### 9.4 组件能力与对象模型

“组件”不再只表示预设卡片、表格等 HTML 组件。任何文字段落、图片、卡片、表格或布局对象都可拥有组件级操作能力。

对象数据至少区分：
- objectKind：TEXT / IMAGE / COMPONENT / TABLE / LAYOUT。
- objectId：稳定且唯一的 ID，复制时生成新 ID。
- parentId / containerId：所在父容器或栏位。
- order：同一容器内的顺序。
- locked / visible：锁定与可见状态。
- style：对象自身样式；imageAssetId 仅在图片对象中保存资源引用。

对象本身的编辑类型和组件能力是两回事：文字仍用文字命令编辑，图片仍用图片命令编辑，但两者都能通过组件工具移动、排序、对齐、锁定、复制和调整层级。

组件悬浮窗口作为可主动打开的辅助工具保留：在现有对象快捷悬浮窗中增加“组件”按钮；点击后显示组件悬浮窗口。选中对象后允许上下左右拖动；位于多栏容器时允许跨栏左右移动。拖动只改变对象在其合法父容器中的顺序/位置，不得破坏表格结构或把 DOM 节点移出编辑根节点。拖动完成后写入历史、更新 HTML、刷新图层列表和对象选中状态。

### 9.5 Compose / WebView 职责

Compose：
- 管理导航状态（DEFAULT / TEXT / IMAGE / COMPONENT）、底栏项目和面板路由。
- 管理系统图片选择器、文字输入焦点/键盘、模板收藏持久化、调色/阴影等参数面板。
- 处理工具面板滚动与拖动手势冲突、系统导航区 Insets。
- 底栏在同一屏幕位置切换；选中对象时不叠加第二条底栏。

WebView / JavaScript：
- 负责 DOM 对象识别、对象 ID、文字双击状态、Selection/Range 保存恢复。
- 负责文字/图片/组件样式和顺序命令。
- 负责同一父容器内上下/左右拖动、多栏目标命中、锁定限制。
- 每次成功修改都调用统一历史提交、正文变更通知和选择状态回传。
- 通过结构化 Bridge 回传 objectKind、objectId、parentId、选区状态、边界矩形、locked、selectedIds；旧 Bridge 回调在迁移期间保留，避免破坏现有入口。

### 9.6 实施顺序与回归门槛

1. **P0：构建基线修复**。修复底部面板 patch 的换行定位错误，先让当前 main 的 Kotlin 检查与 APK 工作流恢复成功。
2. **P1：对象状态与底栏状态机**。增加 TEXT/IMAGE/COMPONENT 三类底栏切换；第一次点击文字只选中、第二次/编辑进入键盘；点击空白恢复默认底栏。
3. **P2：文字底栏**。接入四个文字2 tab、段落对齐、段落副本、复制/粘贴、复制样式、收藏、多选、锁定。
4. **P3：图片底栏**。接入替换、裁切、调色、透明度、边框、圆角、阴影、翻转、对齐、复制/样式复制/粘贴、背景图。
5. **P4：组件移动与悬浮工具**。组件快捷悬浮窗增加入口；支持任意文字/图片作为组件被拖动、跨栏移动、锁定/解锁和顺序管理。
