拾万句 需求说明书

一个把文案、配图、动图、往期和账号信息，快速排成公众号文章的工具。本文档以现有网页版的实际行为为准，用来指导 Android 原生版的实现与验收。

版本1.0 范围排版页 · 我的 基准网页版（排版 + 我的 两个页面） 平台Android 8.0+

1　产品概述

1.1　定位

运营者每天要把一批短句排成固定样式的公众号内容：选版式、选文案、配图、插入动图和往期推荐，再放进公众号编辑器。拾万句把这套动作压缩成“点几下，预览立刻出来”。

1.2　核心流程

  1. 在【我的】里维护素材：账号、文案、版式、emoji、往期、动图、配图。
  2. 回到排版页，依次选择：账号 → 版式 → 文案（含数量、倍率）→ 配图 → 更多（emoji / 动图 / 往期）。
  3. 预览区实时重排；点【编辑】进入编辑模式，直接改字、调边距、加空行、取随机标题。
  4. 把预览内容复制到公众号编辑器。

1.3　名词

名词含义
版式一段 HTML 模板，包含若干重复的“条目单元”。共四种：朋友圈版、文字断句版、卡片版、断章序引版。
条目 / 单元版式里重复出现的最小结构，每个条目对应一条文案。
文案模块一个有名字的文案集合，每行一条；分类为“朋友圈”或“名句”；另有“标题”字段，每行一个随机标题。
出处文案里破折号后面的作者 / 书名，如“……——史铁生《我与地坛》”。
数量 / 倍率数量 = 排几个条目；倍率 = 每个条目里放几句文案（x1~x5）。
往期 / 动图预览末尾可追加的两种内容块：往期推荐（5 条文章）和动图代码块。

2　信息架构

拾万句
├─ 排版页
│   ├─ 顶部栏：标题 · 字数 · 导出 · 编辑/完成
│   ├─ 预览区（可编辑，含编辑悬浮窗）
│   ├─ 二级面板（随一级导航变化）
│   └─ 一级导航：账号 · 版式 · 文案 · 配图 · 更多 · 我的
└─ 我的
    ├─ 账号
    ├─ 文案   （宫格 / 列表 · 手动排序）
    ├─ 版式
    ├─ 更多   （emoji · 往期 · 动图 · 配图）
    └─ 备份   （导出 / 导入 JSON）

两个页面共用同一份数据。在【我的】里修改后返回排版页，已选内容会重新校验，预览随之刷新。

3　数据模型

备份文件是一份 JSON，网页版与 Android 版必须互相可导入。字段名不可改。

{
  "accounts": [{ "id", "avatar", "name", "appId", "secret", "mpAvatar", "author" }],
  "layout":   [{ "id", "name", "content" }],                     // content = 模板 HTML
  "history":  [{ "id", "name", "title", "link", "image", "content" }],
  "emoji":    [{ "id", "name", "content" }],
  "files": {
    "text":  [{ "id", "name", "title", "content", "category" }], // category: 朋友圈 | 名句
    "gif":   [{ "id", "name", "content" }],                      // 两个换行分隔多段代码
    "image": [{ "id", "name", "content" }]                       // 每行一个图片地址
  },
  "layoutVer": 2
}

3.1　规范化规则

  • 缺失或重复的 id，按列表顺序补确定性 id（acc_1、layout_1、file_text_1……）。id 一律当字符串比较，数字 id 视为字符串。
  • 所有文本字段缺失时补空字符串。
  • 文案模块的 category 不在“朋友圈 / 名句”内时，默认“朋友圈”。
  • layoutVer 低于当前版本（2）时，按版式名称把内容替换为最新模板：名称含“卡片 / 断章或序引 / 朋友圈 / 断句”分别对应四种版式；替换后写入当前版本号。
  • 导入备份必须包含 accounts 数组和 files 对象，否则提示“备份文件格式不正确”。

3.2　往期条目的保存

往期有“标题 / 链接 / 图片”三项。保存时同时生成 content：有图片 → 图片版代码；无图片 → 文字版代码。旧数据没有这三项时，直接输出原 content。

4　排版页

4.1　布局

┌────────────────────────────┐
│ 拾万句   1234字   [导出][编辑] │ 顶部栏
├────────────────────────────┤
│                            │
│        预览区（白底）         │ 可滚动、可编辑
│                            │
├────────────────────────────┤
│  二级面板（随一级导航变化）     │
├────────────────────────────┤
│ 账号 版式 文案 配图 更多 我的   │ 一级导航
└────────────────────────────┘

默认进入【文案】。字数按 Unicode 字符计，含空格、换行、emoji。

4.2　一级导航与二级面板

一级二级面板内容交互
账号账号卡片列表；默认选中第一个点击选中；朋友圈版头像随之更换。无账号时提示去【我的】添加。
版式版式缩略卡（名称 + 配色 + 示意图）点击切换，预览重排。
文案二级导航“朋友圈 / 名句”（默认朋友圈）+ 右侧数量控件；下方是该分类下的文案模块点击模块 = 随机读取；再次点击同一模块 = 重新随机。
配图“重新随机”按钮 · 当前配图模块名 · 备选缩略图已用于预览的缩略图高亮。
更多二级导航 emoji / 动图 / 往期见 4.5。
我的—进入【我的】页面。

4.3　数量与倍率（文案面板右上角）

  • 数量：快捷 3 / 6 / 9，加一个自定义输入框；默认 9。输入大于 0 的整数即时生效。
  • 倍率：数量右侧的 x1 按钮，点击循环 x1→x2→x3→x4→x5→x1，默认 x1。
  • 没有单独的“数量”一级导航。数量同时决定配图的使用张数。

4.4　文案模块的选择

  • 选中模块后，从该模块的内容里随机抽取最多 80 条作为文案池（保证数量 15 × 倍率 5 也够用）。
  • 该分类下没有模块时提示“【分类】下暂无文案，可在【我的】-文案中添加”。
  • 没有选中任何文案时，预览保留模板自带的示例文字。

4.5　更多：emoji / 动图 / 往期

项行为
emoji点任意 emoji 条目 = 从全部 emoji 条目里随机取一个，再从其内容（按空行分段）里随机取一段，作为“预览 emoji”追加到每个条目的序号 / 昵称 / 引号之后（见 5.13）。
动图点动图条目 = 从其内容（按两个换行分段）里随机取一段，插入预览末尾。
往期面板只有“随机5条 / 重新随机5条 / 移除往期”和“共 N 条”。每次随机读取 5 条往期条目，插入预览末尾。

动图与往期都是“先点先插入”：谁先被点，谁排在前面；已经插入的再次点击，位置不变。点击后预览自动滚动到该块。

4.6　预览区

  • 白底，左右各 15px 内边距；内容按“版式 → 动图 / 往期（按点击顺序）”从上到下排列。
  • 非编辑模式下文字不可选；动图块始终可选中，编辑模式下整个预览区可选中、可编辑。
  • 没有任何版式时显示“暂无版式，请到【我的】中添加”。

4.7　编辑模式与悬浮窗

点【编辑】进入，按钮变为【完成】。进入时自动弹出“随机标题”悬浮窗；预览区左侧出现两个入口图标：编辑设置、随机标题。退出时两个悬浮窗都收起。

  • 悬浮窗通用特性：可拖拽（拖标题栏）、可缩放（拖右下角）、位置与尺寸限制在预览容器内；最小 190×96；点到哪个窗口，哪个窗口置顶；样式取主题色。
  • 随机标题：见 5.19；带【复制】和【换一个】。复制成功后按钮短暂显示“已复制”。
  • 编辑设置：
    • 往期 / 动图边距：一套配置，同时控制预览里的往期块和动图块。四个数值，顺序为上、右、下、左（px），可直接输入，也可点 ▲▼ 微调；输入框一激活就清空，失焦时若为空则恢复原值；修改实时作用到预览，且不重新渲染，已编辑内容不丢失。
    • 全局空行：【内容上方】【内容下方】两个独立开关，各插入 1 个空行，见 5.17。

5　排版引擎规则最核心的部分，Android 需逐条等价实现

引擎的输入是：当前数据 + 界面状态（所选版式、账号、文案池、配图池、数量、倍率、动图、往期、边距…），输出是预览区的 HTML。每次状态变化都整体重算。

5.1

单元识别

  • 去掉模板里所有 script；顶层元素里的 style 原样保留在容器内。
  • 只有 1 个顶层元素、且它的子元素“只有 1 个”或“由重复结构构成”时，把它当作外层容器，容器内部的子元素作为单元序列；否则顶层元素序列本身就是单元序列。
  • “重复结构”：按标签名序列求最小周期 p（p 能整除总数，且每个元素与 i mod p 处标签相同）。每 p 个元素构成一个单元。
5.2

条目数

有文案时：条目数 = min(数量, 文案池条数)；没有文案时：min(数量, 模板单元数)。单元不够时循环复用。

5.3

文案排序

取文案池的前“条目数”条，按正文字符数由少到多排序（正文不含出处；同字数保持原先后），预览按这个顺序输出。字符数按 Unicode 码点计。

5.4

序号与时间

单元里纯数字文本（1~3 位）替换为两位序号（01、02…）；“N分钟前”替换为“(i+1)分钟前”。只有在有文案时才替换。

5.5

正文定位

在单元的文本节点里，排除序号、PART、纯引号类字符后，取不含“《”的最长文本作为正文位置；紧随其后的下一个文本节点视为出处位置。

5.6

出处解析

  • 双破折号及以上（——、――、--、──）之后的文本，长度 ≤ 40 字，视为出处。
  • 单个破折号（—、―、－、-）只有在后面带“《……》”时才算出处，避免误拆“我—你”这类句子。
  • 不满足时整行都是正文，没有出处。
5.7

出处输出（按版式）

版式有出处无出处
朋友圈版不展示出处，也不会把出处拼到正文里。
文字断句版在正文下方输出一个整行 span：display:block，内层 <span leaf> 放出处。移除出处元素。
卡片版输出灰色小字 div：margin:14px 0 0 0; color:#999; font-size:13px; line-height:2.1。移除出处元素。
断章序引版输出加粗段落 <p><strong><span leaf>出处。移除出处段落，同时移除它上方的空白占位段落。
5.8

倍率 xN

每个条目共 N 句：第 1 句是排序后的主文案，另外 N−1 句取自文案池（第 j 句取 池[(条目数×j + i) mod 池大小]，只取正文），追加到正文容器内，用两个换行与前一句分隔。追加位置：

  • 卡片版：样式含 overflow-wrap:anywhere 的 div 内；
  • 朋友圈版：样式含 white-space:pre-wrap 的 div 内，直接用 \n\n；
  • 断章序引版、文字断句版：<span leaf> 内。
  • 容器不保留换行时，用两个 <br> 代替。
5.9

配图

  • 配图池：随机选一个有可用地址的配图模块，再随机取 20 张。条目 i 使用 池[i mod 池大小]。
  • 地址规范化：支持 http(s)、// 开头、省略协议的域名（如 shturl.cc/xxx，补 https）、data:image、<img src> 与 Markdown 图片写法；其余行丢弃。
  • 模板里宽度 ≤ 64px 的图片视为头像，不替换。
  • 显示时 http 升级为 https，加载失败回退到原地址；图片关闭 Referer（绕过图床防盗链）。
5.10

朋友圈版专属

  • 头像：取当前选中账号的“头像”链接（微信头像，http://wx.qlogo.cn 自动改 https），切换账号即时更换；链接无效时回退到模板自带头像。
  • 图片正方形：内容图片（非头像）统一 aspect-ratio:1/1; object-fit:cover，高度等于其宽度。
5.11

条目间距

每个版式的相邻条目之间统一 25px（给非最后条目的末尾元素加 margin-bottom:25px !important）。最后一个条目去掉尾部间距（断章序引版同时隐藏末尾空白占位段落），这样与往期 / 动图的间距完全由边距设置决定。

5.12

断章序引版配色

整个预览里没有子元素的文字元素统一设为深灰 #333333，但位于“序号段落（样式含 #999）”里的保持原色。

5.13

预览 emoji

选中 emoji 后，在每个条目里追加一个几乎不占空间的 span（宽 1px、高 1px，内容为 4 个空格 + emoji）：朋友圈版放在每个“拾万句”昵称内；卡片版放在每个左引号“ “ ”内；其余版式放在每个序号文本之后。同一位置不重复插入。

5.14

往期块

  • 有图片的条目合并成图片版：一行 5 列等宽表格，图片比例 1 : 1.15，圆角 3px，图下一行标题（10px，单行省略）；图片可点击跳转链接；不足 5 条用空列补齐。
  • 无图片的条目是文字版：每条一行，链接色 #44546A、下划线、12px；没有链接就只显示文字。
  • 旧数据（没有标题 / 链接 / 图片）按原 content 输出。
5.15

动图块

取随机到的那一段代码；统一放开“不可编辑”，图片不可拖拽；块始终可被选中（包括编辑模式）。

5.16

往期 / 动图边距

版式默认（上 右 下 左）
朋友圈版25 · 25 · 0 · 55
断章序引版16 · 15 · 16 · 15（上下沿用原有）
卡片版 / 文字断句版16 · 0 · 16 · 0
  • 用户修改后，按版式种类分别记忆。
  • 左右边距相对预览容器左右边界计算：数值增大，块宽度被压缩；数值减小，块宽度拉伸（块宽度为自适应，不是固定 100%）。
  • 上下边距控制该块与上下相邻内容块的间距：数值越大，间距越大。往期与动图上下相邻时，二者之间的间距取下边距与上边距中较大的一个。
5.17

全局空行

  • 基准是鼠标选中行 / 光标所在行：在该行上方或下方插入一个高 1.8em 的空行块。
  • “行”= 光标所在位置最近的块级元素；在表格单元格里取整张表；位于 flex / grid 排布的一行里时，取整行容器。
  • 不支持在页面全局第一行的上方和全局最后一行的下方插入（判断：该行之前 / 之后没有任何文字或图片）。窗口里会给出“已是全局首行 / 末行”提示。
  • 开关打开后，空行跟随光标所在行移动；还没点选任何行时开关不生效，并提示“请在预览中点击一行文字”。
5.18

选区校验

数据变化（如在【我的】里改动）后：已选文案若不在新内容里则移除；文案池清空则重抽；配图池同理；已选动图 / 往期被删除则清除；没有往期时从“插入顺序”里去掉往期。

5.19

随机标题

  • 跟随当前所选文案模块：选中“短句”就只读“短句”的标题；没有选中任何模块时，读当前分类下所有模块的标题。
  • 标题字段按单个换行符分割，去掉空行，再随机选一条；连续两次尽量不重复。
  • 没有可用标题时分别提示：“所选文案「X」暂无标题，请到【我的】-文案中填写标题。”或“暂无标题，请先选择文案……”。
  • 切换文案模块时，若标题窗口开着，标题自动重新读取。

6　我的

浅色页面。所有带标签栏的页面，选中项用主题色填充（文字取对比色），不使用固定蓝色。

6.1　首页

五个入口，每个附一行摘要：账号（已配置 N 个账号）、文案（共 N 个文案模块）、版式（已保存 N 个版式）、更多（共 N 个数据模块）、备份。左上角返回排版页。

6.2　账号

列表 + 新增 / 编辑 / 删除（删除前确认）。字段：微信头像链接、账号名称、AppID、AppSecret、公众号头像、作者。名称为空时存为“未命名账号”。

6.3　文案

  • 页面标题“文案”，没有内部标签导航，只管理文案模块。
  • 字段：名称、分类（朋友圈 / 名句，新建默认名句）、标题（每行一个）、内容（每行一条）。
  • 视图模式：右上角在“宫格 / 列表”间切换。宫格为4 列（4×n），每格显示名称和两行摘要；所选模式持久化，直到下次切换。
  • 手动排序：默认隐藏。点【排序】进入，条目右侧出现 ≡，按住上下拖动调整顺序，松手自动保存；点【完成】退出，退出后恢复所选视图。排序结果同步到排版页的文案模块顺序。

6.4　版式

列表 + 新增 / 编辑 / 删除。字段：配置名称、模板代码（HTML）。名称里要包含“朋友圈 / 文字断句 / 卡片 / 断章序引”之一，才会套用对应的出处、倍率、头像规则。

6.5　更多

顶部标签栏，顺序固定：emoji · 往期 · 动图 · 配图。

标签字段说明
emoji名称、内容内容里多个 emoji 用空行分隔，随机取一个。
往期标题、链接、图片图片留空为文字版；保存时按模板生成渲染代码。

类别内容保存

9　Android 实现Kotlin · Jetpack Compose

9.1　技术选型

  • 界面全部用 Jetpack Compose 原生实现；单 Activity，状态集中在一个 ViewModel。
  • 排版引擎用 Kotlin + Jsoup 重写，不依赖网页：输入数据和状态，输出预览 HTML。
  • 预览区用 WebView 渲染该 HTML——因为产物本身就是公众号 HTML，需要富文本选中、编辑、复制。WebView 里只放一页很薄的壳（preview.html），负责：渲染、编辑开关、边距实时更新、空行（光标行判断）、字数统计，并通过 JavascriptInterface 回传字数和基准行。
  • 数据以 JSON 文件保存（字段与备份一致）；界面状态用 SharedPreferences；图片缩略图用 Coil。
